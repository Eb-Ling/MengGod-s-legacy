# 生涯位置

来源：原版 Starsector。

## 定义

生涯位置是原版生涯地图中承载星系、超空间、实体集合、舰队集合、位置脚本、背景、粒子和访问状态的接口集合。

## 参考

- `com.fs.starfarer.api.campaign.LocationAPI`：提供星系、超空间等 location 的实体容器、地形、脚本、memory 和背景入口。
- `com.fs.starfarer.api.campaign.LocationAPI.addCustomEntity(...)`：提供 custom entity 的 location 容器创建入口。
- `com.fs.starfarer.api.campaign.LocationAPI.addPlanet(...)`：提供行星或恒星的 location 容器创建入口。
- `com.fs.starfarer.api.campaign.LocationAPI.addTerrain(...)`：提供地形实体的 location 容器创建入口。
- `com.fs.starfarer.api.campaign.LocationAPI.createToken(...)`：提供临时位置 token 创建入口。
- `com.fs.starfarer.api.campaign.SectorAPI`：提供所有 location 的注册、查询、当前 location、超空间和星系创建入口。
- `com.fs.starfarer.api.campaign.SpawnPointPlugin`：提供旧式 location 刷新点入口。
- `com.fs.starfarer.api.campaign.StarSystemAPI`：提供星系 location 的恒星、中心、超空间锚点、自动跳跃点和星座入口。

## 边界

- `LocationAPI` 归属星系、超空间、实体集合、舰队集合、行星集合、地形集合和脚本集合。
- `LocationAPI.addCustomEntity(...)` 归属 custom entity 的 location 容器创建入口。
- `LocationAPI.addEntity(...)` 归属已有实体加入 location 容器的入口。
- `LocationAPI.addPlanet(...)` 归属行星和恒星的 location 容器创建入口。
- `LocationAPI.addTerrain(...)` 归属地形实体的 location 容器创建入口。
- `LocationAPI.createToken(...)` 归属位置 token 的创建入口。
- `LocationAPI.getAllEntities()` 归属 location 内全部实体集合读取。
- `LocationAPI.getCustomEntities()` 归属 location 内 custom entity 集合读取。
- `LocationAPI.getEntityById(id)` 归属 location 内按 id 查询实体。
- `LocationAPI.getFleets()` 归属 location 内舰队集合读取。
- `LocationAPI.getGravityWells()` 归属 location 内 nascent gravity well 集合读取。
- `LocationAPI.getMemoryWithoutUpdate()` 归属单个 location 的 memory 读取。
- `LocationAPI.getPlanets()` 归属 location 内行星集合读取。
- `LocationAPI.getPersistentData()` 归属单个 location 的持久化对象 Map。
- `LocationAPI.getScripts()` 归属单个 location 的按帧脚本集合。
- `LocationAPI.getTerrainCopy()` 归属 location 内地形集合读取。
- `LocationAPI.removeEntity(...)` 归属实体从 location 容器移除的入口。
- `SectorAPI` 归属所有 location 的注册、查询、当前 location、超空间和星系创建入口。
- `SpawnPointPlugin` 归属旧式 location spawn point 推进入口。
- `StarSystemAPI` 归属星系专有恒星、中心、超空间锚点、自动跳跃点、星座和访问状态。
- location 背景归属 `LocationAPI` 的背景贴图、背景偏移和背景颜色 shifter。
- location 粒子归属 `LocationAPI` 的 hit particle 与 particle controller 创建入口。

## 链路

### Location 脚本链路

1. 代码取得 `LocationAPI`。
2. 调用 `addScript(script)` 注册 location 脚本。
3. location advance 时检查脚本的 `runWhilePaused()`。
4. location advance 时调用脚本的 `advance(amount)`。
5. `isDone()` 返回 true 后脚本进入清理。
6. 调用 `removeScript(script)` 或 `removeScriptsOfClass(clazz)` 移除脚本。
7. 调用 `getScripts()` 读取脚本集合。

### Location 查询链路

1. 代码通过 `SectorAPI.getHyperspace()`、`getStarSystem(name)`、`getCurrentLocation()` 或 `getAllLocations()` 取得 location。
2. 调用 `getEntityById(id)` 查询 location 内实体。
3. 调用 `getEntitiesWithTag(tag)` 查询带 tag 的实体。
4. 调用 `getCustomEntitiesWithTag(tag)` 查询带 tag 的 custom entity。
5. 调用 `getFleets()` 读取 location 内舰队集合。
6. 调用 `getPlanets()` 读取 location 内行星集合。
7. 调用 `getTerrainCopy()` 读取 location 内地形集合。
8. 调用 `getAllEntities()` 读取 location 内全部实体集合。

### Location 实体容器链路

1. 代码取得 `LocationAPI`。
2. 调用 `createToken(...)` 创建位置 token。
3. 调用 `addPlanet(...)` 创建行星或恒星实体。
4. 调用 `addCustomEntity(...)` 创建 custom entity。
5. 调用 `addTerrain(...)` 创建 terrain entity。
6. 调用 `addAsteroid(...)`、`addAsteroidBelt(...)`、`addRingBand(...)` 或 `addCorona(...)` 创建视觉或地形实体。
7. 调用 `addEntity(entity)` 把已有实体加入 location。
8. 调用 `removeEntity(entity)` 从 location 移除实体。
9. 调用 `updateAllOrbits()` 更新 location 内轨道状态。

### Star system 创建链路

1. 代码调用 `SectorAPI.createStarSystem(name)` 创建 `StarSystemAPI`。
2. 调用 `initStar(...)` 或 `initNonStarCenter()` 初始化星系中心。
3. 调用 `setLocation(...)` 或读取 `getLocation()` 处理星系在超空间中的坐标。
4. 调用 `addPlanet(...)`、`addCustomEntity(...)`、`addTerrain(...)` 和 `addRingBand(...)` 填充星系内容。
5. 调用 `generateAnchorIfNeeded()` 创建主超空间锚点。
6. 调用 `autogenerateHyperspaceJumpPoints(...)` 创建自动超空间入口。
7. 调用 `getAutogeneratedJumpPointsInHyper()` 或 `getAutogeneratedNascentWellsInHyper()` 读取自动生成结果。

## 规范

- `LocationAPI.activeThisFrame()` 对当前 location 总是返回 true。
- `LocationAPI.addCustomEntity(...)` 的 factionId 缺省语义为 neutral。
- `LocationAPI.addRingBand(...)` 的 terrain 版本返回 terrain entity。
- `LocationAPI.createToken(...)` 创建的 token 可在需要轨道时通过 `addEntity(...)` 加入 location。
- `LocationAPI.getCustomEntitiesWithTag(...)` 只遍历 custom entity 集合。
- `LocationAPI.getEntityById(id)` 是按 id 查询 location 内实体的入口。
- `LocationAPI.getFleets()` 返回 location 内舰队集合。
- `LocationAPI.getMemoryWithoutUpdate()` 返回 location memory。
- `LocationAPI.getPersistentData()` 返回 location 持久化 Map。
- `LocationAPI.getTerrainCopy()` 返回 location 内 campaign terrain 副本。
- `SectorAPI.getAllLocations()` 返回所有星系和超空间。
- `SectorAPI.getEntityById(id)` 会遍历所有 location。
- `SectorAPI.getEntitiesWithTag(tag)` 会遍历超空间和所有星系。
- `SectorAPI.getHyperspace()` 返回超空间 location。
- `StarSystemAPI.autogenerateHyperspaceJumpPoints()` 调用无参版本时使用两个 false 参数。
- `StarSystemAPI.getHyperspaceAnchor()` 返回星系中心对应的超空间 token。
- `StarSystemAPI.getOptionalUniqueId()` 可供 `SectorAPI.getStarSystem(String)` 查询使用。
- `StarSystemAPI.initStar(...)` 带超空间坐标的版本会自动创建通向恒星的 wormhole。

## 陷阱

- `LocationAPI.addRingBand(...)` 的 terrain 版本返回 terrain entity。
- `LocationAPI.createToken(...)` 创建的 token 初始状态不在 location 实体集合中。
- `LocationAPI.getEntityByName(...)` 已废弃，按 id 查询使用 `getEntityById(...)`。
- `LocationAPI.getOrbitalStations()` 已废弃，空间站查询使用 station tag。
- `StarSystemAPI.initStar(...)` 常规版本不会自动生成超空间锚点。
