# Java Guidelines

本文件维护 Java 的结构、控制流和排版规则。

## 状态与生命周期

- 状态必须由直接拥有其生命周期的对象保存。
- 创建、复用与注销必须收束在正式入口。
- 清理只能释放当前对象实际写入或持有的状态。
- 临时关系禁止成为字段；跨帧字段只能表示长期有效事实。
- 查询方法必须无副作用。
- 可由现有字段、当前 API 或局部计算立即取得的值禁止缓存为字段。

## 控制流

### 过滤

- 同层级、同出口、同目的的连续 guard 必须写成多个连续的单行 if。
- 每个 guard 必须独占一行，条件与 return 或 continue 必须写在同一行。
- 循环中的连续过滤必须写成单行 continue。

### 业务分支

- 普通业务分支与非并列 if 必须使用多行块。
- 含赋值、注册、创建、清理、状态推进或外部调用的分支，即使只有 1 条语句也必须使用多行块。
- for 与 while 的循环体必须使用多行块，即使循环体只有 1 行。
- 能由提前 return 或 continue 表达的 else 必须消解。

## 方法

### 语义边界

- 可信的内部调用链禁止增加不必要的空值防御。
- 只负责推进业务状态的方法必须返回 void。
- 方法体禁止压成单行。
- 业务判定、生命周期、注册和清理方法必须保留为语义入口。
- 单路径状态机必须优先留在正式入口内，禁止拆成只由该入口调用的碎片方法。
- 单次调用、单个条件或单步转发禁止单独建类型。

### 行数边界

- 普通方法以 50 行为上限目标。
- 超过 50 行只允许用于正式入口、外部回调、UI 构建、AI 决策、生成流程或不可拆顺序流程。
- 超过 150 行只允许用于高度耦合的入口流程。
- 少于 5 行的方法必须承担业务判定、生命周期、注册或清理入口；否则严禁保留。

## 排版

- Java 缩进必须使用 tab。

### 方法空行

- 方法超过 5 行时，签名与主体之间允许 1 行空行；不超过 5 行时方法内严禁空行。
- 空实现的方法体必须保留 1 行空行。
- return 前仅在结束较长逻辑段时允许 1 行空行，return 后严禁空行。

### 控制块空行

- 简短控制块必须直接进入首条语句。
- 控制块内开始独立语义段时允许先空 1 行，但随后必须是真实语句或注释。
- 空行严禁用于伪造空控制块。
- 循环头与循环内的批处理段之间允许 1 行空行。

### 语义段空行

- 同级语义段之间必须空 1 行。
- 变量声明组与后续判断、循环或动作之间必须空 1 行。
- 连续 guard 与主体之间必须空 1 行。
- 连续空行必须合并为 1 行。

## 注释

- 注释必须使用英文并独占一行，严禁行尾注释。
- 只允许用少量注释说明判定意图、数值来源、阶段意义或非显然约束。
- 注释严禁复述代码动作。
- 复杂数值、经验参数与阶段比例允许用短注释记录推导。
- 块注释只允许保存较大设计草稿或暂存片段；Javadoc 不作为默认说明形式。

## 命名与类型

- 同一业务概念禁止在字段、方法和局部变量名中重复堆叠上下文词。
- 名称必须直接表达业务语义，同一概念必须保持一致粒度。
- 类型必须拥有独立状态、生命周期或行为职责。
