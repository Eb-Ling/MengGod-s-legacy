一、表格数据格式（CSV 结构）
======================================================================

规则定义在 data/campaign/rules.csv 的 "Starsecutor Rules" 工作表中，每行包含以下五列：

+-------------------+--------------------------------------------------+
| 列名              | 说明                                             |
+-------------------+--------------------------------------------------+
| Trigger（触发器） | 触发该规则的事件类型（见第二章）                 |
| Conditions（条件）| 所有条件必须满足，规则才会被执行（见第三章）     |
| Script（脚本）    | 执行的表达式和命令（见第四、七、八章）           |
| Text（文本）      | 添加到对话框中的显示文字（见第五章）             |
| Options（选项）   | 显示给玩家的交互按钮（见第六章）                 |
+-------------------+--------------------------------------------------+

【开发者福音】在 Dev 模式下修改该 CSV，游戏会自动热重载，无需退出当前对话框即可生效。


二、触发器（Triggers）
======================================================================

触发器是规则的入口。以下是硬编码的内置触发器：

  Trigger 名称                   触发时机
  ---------------------------  ------------------------------------------------
  OpenInteractionDialog        对话框首次打开时
  DialogOptionSelected         玩家选择某个对话框选项时
  BeginFleetEncounter          舰队遭遇对话框打开时
  OpenCommLink                 玩家打开通讯链接时（舰队遭遇或其他场景）

【注】触发器本质是任意字符串，Mod 可通过代码自定义扩展。


三、条件（Conditions）
======================================================================

1. 每条规则可设置零条或多条条件，必须全部满足才匹配。

2. 匹配模式：
   - FireBest（最佳匹配）：计算得分，最高者执行。
     得分公式 = 条件数量 + 各条件的 score 附加值（若有）。
     若同分则随机选取。
   - FireAll（全部匹配）：执行所有满足条件的规则（常用于生成选项列表）。

3. 加权修饰符：
   在条件后追加 "score:<整数>" 可增加权重，例如：
     respondingToCommRelayInterference score:100
   该条件权重为 100，会极大提升规则胜出概率。


四、脚本（Script）
======================================================================

脚本由表达式组成，每行一个表达式，按顺序执行。包含：
  - 运算操作（变量赋值、比较、自增等）
  - 高级命令（等待、中断、显示UI、触发子规则等）


五、文本（Text）
======================================================================

1. 规则匹配后，将此文本添加到对话框。

2. 随机变体：用单独一行的 "OR" 分隔，系统会随机选择一条。例如：
     文本一
     OR
     文本二

3. 令牌替换：支持 $变量名 替换。若内存变量与游戏内置令牌重名，内置令牌优先。


六、选项（Options）
======================================================================

1. 若规则包含 Options 字段，当前所有旧选项将被清空，然后添加新选项。

2. 格式：<排序>:<选项ID>:<选项文本>
     - 排序（可选）：用于 FireAll 时控制多个选项的排列顺序。
     - 选项ID：当前对话框内唯一即可。

3. 自动回写：当玩家点击选项触发 DialogOptionSelected 事件时，选中的 ID 会自动写入变量 $option。


七、变量与内存上下文（核心机制）
======================================================================

7.1 内存作用域（前缀规则）

每个变量都有所属的内存上下文，通过前缀指定：

  前缀             上下文             生命周期与可见性
  --------------  -----------------  -----------------------------------------
  （无）或 local. 本地内存（默认）   仅当前交互实体（如某个中继器）有效
  global.         全局内存           全局共享，跨规则、跨实体
  faction.        派系内存           当前实体所属派系共享
  market.         市场内存           实体所在的市场共享
  player.         玩家内存           与 global 类似，仅用于逻辑归类

  示例：
    $menuState           → 存入本地内存
    $global.menuState    → 存入全局内存
    $blah.menuState      → 因无 "blah" 上下文，实际存入本地，变量名为 "blah.menuState"

7.2 预置"事实"（Facts）

游戏核心会自动写入一些内置变量：
  - 标签：$tag:<标签名>（如 $tag:comm_relay、$tag:station）
  - 其他：派系、舰队点数、战力对比、关系值等。

7.3 字面量（Literals）

  - 不以 $ 开头的视为字面量（字符串/数字/布尔）。类型由上下文自动推断。
  - 包含空格或运算符的字符串需用双引号包裹，内部双引号用 \" 转义：
      main                    → 字符串 "main"
      main menu               → 字符串 "main menu"
      "main \"menu\""         → 字符串 main "menu"

7.4 句柄（Handles）

  变量可作为"句柄"指向 Java 对象（如 Wait 对象），用于命令间传参，脚本不直接操作。


八、运算操作（Operations）
======================================================================

8.1 赋值 "="
  左操作数必须是变量，右操作数可为变量或字面量。
  可选第3参数：过期时间（游戏天数），到期自动清除。
    $menuState = main           # 无过期
    $menuState = main 0         # 退出对话框时立即过期
    $menuState = main 1.5       # 1.5 游戏天后过期（约15秒非暂停时间）

8.2 自增/自减 "++" / "--"
  可选参数：重置过期时间。
    $counter++                  # 自增，不重置过期
    $counter++ 10               # 自增，并重置为10天后过期

8.3 无操作（No-op）—— 真值判断
  单独写一个变量名。当且仅当该变量的值为字符串 "true"（不区分大小写）时返回真。
  【警告】非零数字会被判定为 false！
    $commSnifferInstalled       # 检查是否为字符串 "true"

8.4 比较运算符
  支持：== , != , > , < , >= , <=
    $menuState == main
    $global.pirateFleetsDefeated >= 10

8.5 逻辑非 "!"
  仅作用于变量，取反。
    ! $commSnifferInstalled


九、高级命令详解（Commands）
======================================================================

命令名对应 Java 类，区分大小写，位于 starfarer.api/.../rulecmd 包下。

9.1 Wait —— 等待（异步）
  关闭对话框，将玩家舰队"拴住"指定天数。可被玩家挣脱或被其他脚本中断。
  用法：
    Wait <句柄> <时长> <完成变量> <中断变量> <进行中变量>
  参数详解：
    - 句柄：存储 Wait 对象引用，用于 AbortWait。
    - 时长：游戏天数。
    - 完成变量：成功完成时设为 true，立即过期。
    - 中断变量：被中断时设为 true，2 天后过期。
    - 进行中变量：等待期间为 true，快速过期。
  示例：
    Wait $global.csWait 0.5 $global.csFinished $global.csInterrupted $global.csInProgress
  【警告】必须使用全局变量！确保外部实体（如巡逻队）能访问并中断等待。

9.2 AbortWait —— 中断等待
  取消正在进行的等待，清理相关变量。不会设置"中断变量"。
    AbortWait $global.csWait

9.3 DismissDialog —— 关闭对话框
  立即关闭对话框并取消暂停。无参数。
    DismissDialog

9.4 expire —— 设置变量过期
  设置指定变量的过期时间（游戏天数）。
    expire $menuState 1

9.5 unset —— 立即删除变量
  从内存中彻底移除变量。
    unset $menuState

9.6 FireAll —— 执行所有匹配规则
  执行所有匹配指定触发器的规则。
    FireAll PopulateOptions

9.7 FireBest —— 执行最佳匹配规则
  执行得分最高的那条规则。
    FireBest InitCommRelayDialog

9.8 PrintDescription —— 打印实体描述
  打印自定义描述（若有），<索引> 对应 descriptions.csv 的列号（1/2/3）。
    PrintDescription 1

9.9 ShowDefaultVisual —— 显示默认视觉
  显示自定义交互视觉；若无则显示星球默认图形。
    ShowDefaultVisual

9.10 其他命令（清单）
  以下命令在文档中仅列名称，具体参数请查阅源码或社区示例：
    AddSelector

十、开发者模式调试
======================================================================

1. 热重载：修改 rules.csv 保存后立即生效，无需重启游戏。
2. 内存转储：与实体交互时选择 "dump memory"，可查看所有上下文的变量及其过期状态，极大方便排错。


十一、常见陷阱与最佳实践
======================================================================

【陷阱1】数字真值陷阱
  单独使用 $var 判断时，数字 1 被视为 false。
  正确做法：使用比较运算符 $var > 0 或 $var != 0。

【陷阱2】FireBest 评分陷阱
  高 score: 条件（如 score:100）会使规则轻易胜出，即使条件数量少。请合理设计优先级。

【陷阱3】Wait 与全局变量
  务必为 Wait 使用 global. 前缀变量，否则外部实体无法通过 AbortWait 中断。
  同时注意句柄变量的过期时间，防止 AbortWait 失效。

【陷阱4】选项覆盖机制
  只要某规则提供了 Options 字段，旧选项立刻被全部清除，然后再通过 FireAll 的排序重新构建。

【最佳实践】变量命名
  避免与游戏内置令牌（如 $faction）重名，否则内置令牌优先，可能造成逻辑混乱。
